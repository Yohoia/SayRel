# 录音输入规则

## #8：浮窗与 Electron 后备输入

浮窗开始通过现有 `RecordingMachine.dispatch({ type: 'START' })` 表达免手持开始意图；后备快捷键解析已启用绑定后，发送带模式的 `TOGGLE`。状态机决定是否接受启动、结束当前采集或忽略操作，并在接受启动的第一次状态通知中设置 handsFree。配置缺失、禁用、练习范围不匹配或现有状态导致拒绝时，调用方不再额外修改 handsFree。

浮窗开始是幂等操作：不会结束当前录音，也不会把已有按住录音改成免手持。后备输入没有全局释放事件，继续只提供切换语义；starting 或 recording 时切换会结束当前会话，finishing 与 long_pressing 时忽略。其原有浮窗创建和显示顺序也收进状态机，仍在采集目标上下文前执行。

浮窗结束、取消和重试继续使用现有操作。没有保留音频时，重试经过同一免手持开始规则；有保留音频时，继续复用失败音频及提供商配置快照。会话身份、停止确认、尾帧排空、取消隔离、历史和练习投递仍由原有实现负责。native 物理手势、组合升级和长按计时在 #9 迁移，本阶段保留其行为。

## 行为验证

`scripts/diagnostics/fn-shift-chain.cjs` 通过真实浮窗 IPC 与后备输入入口观察状态、事件和结果，不读取私有 session。原有练习选择文本、翻译目标和会话释放断言也改为观察处理请求或状态。测试使用替代操作系统、音频设备和模型边界，不读取用户配置、不访问麦克风、网络或剪贴板。

新增集成链跨越真实主进程窗口及录音状态 IPC、preload、RecorderSessionController 和 `startRecorder`。替代 Web Audio 设备提供 48kHz 数据，正式采集实现重采样并在结束时排空；2048 个 .25 输入样本的尾部产生 682 个 .25 PCM 样本。检查最终文本只投递一次、音轨与 context 释放、打开设备期间结束、取消后立即开始、旧结果隔离、重试快照和练习所属窗口投递。

另有状态检查覆盖配置拒绝、禁用、练习阻止或模式不匹配、重复开始和结束、finishing 重入及长按提示期间输入。三个新增回归分别在旧后备开始、浮窗开始和无音频重试中复现了拒绝后 `handsFree: true` 的错误。
