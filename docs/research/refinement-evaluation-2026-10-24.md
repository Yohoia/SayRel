# 润写真实模型对照与上屏验证

日期：2026-10-24。范围：已配置的 DeepSeek `deepseek-flash`，`thinkingMode=auto`，听写请求使用生产代码的低 reasoning effort 设置。没有切换模型或修改用户设置。

前两节记录首轮 64 次请求及 `.2` 策略。用户随后明确不接受自动括注，当前版本为 `.3`；追加的 48 次请求和未通过项见文末，不能沿用首轮“20 条最低约束无失败”描述当前质量。

## 实际调用范围

使用生产 `completeChat` 和 prompt 构造函数，凭据从选定 profile 正常解密，仅保留在内存。请求只包含公开/合成测试文本，没有读取录音、历史转写、输入框快照或屏幕上下文用于模型评测。实测输出与 prompt 快照位于被 Git 忽略的 `.build/refinement-evaluation/`。

| 批次 | 范围 | 请求数 | 请求错误 | 最低内容约束失败 |
| --- | --- | --- | --- | --- |
| `baseline-20261024-b` | 6 条文本，各跑原文、轻整理、深整理 | 18 | 0 | 深整理 2 条；其他档位仅留作对照，不套用深整理标准 |
| `baseline-all-20261024` | 20 条文本，原 prompt 深整理 | 20 | 0 | 2 条 |
| `candidate-all-20261024` | 相同 20 条文本，新 prompt 深整理 | 20 | 0 | 0 条 |
| `baseline-repeat-20261024` | 3 条重点文本，原 prompt 再次抽样 | 3 | 0 | 0 条 |
| `candidate-repeat-20261024` | 同 3 条重点文本，新 prompt 再次抽样 | 3 | 0 | 0 条 |

合计 64 次真实请求。第一次启动时曾因持久化配置的默认模型校验失败而退出，未发请求；读取凭据的流程修正后才产生以上数据。没有自动重试或自动切供应商。

**这里不是“准确率从 90% 提升至 100%”。** 检查器主要验证必留内容、禁留片段与顺序，不能完整评价语句自然度。相同输入只做有限抽样，旧版重复抽样也能通过，说明存在生成波动。不能据此宣称稳定性有统计显著改善、其他模型同样有效或所有真实口音/场景已经覆盖。

## 观察到的问题与调整

1. 原版深整理把口头理由直接放进括号。例如待办中的“只住两晚，带登机箱就够了”仍像转写。新版样本出现“只住两晚，够用”等较短注释，但部分停车理由仍然偏口语，未宣称全部达标。
2. 三档对照中的原版深整理曾保留“标题写‘项目复盘’”。新版样本把它应用为标题或会议名称，不再叙述填写标题的动作。
3. 原版一次完整评测保留了 QA 负责人的“名字没有 H”说明。新版对应输出为 `Sarah owns the design review, while Sara owns QA.`，只修正指定人员，没有全局替换另一个 Sarah。
4. 新版在本轮 20 条最低约束中未出现新增失败。仍检查了否定、金额、版本号、引用中的口吃、有意重复、向读者提出的转告/拟稿请求。规则通过不是这些风险在任意输入上被排除的证明。

`dictation-2026-10-24.2` 只给深整理追加最终成文检查：实际应用明确的标题/拼写/顺序指令，压缩口语任务理由，同时保留引用、疑问、不确定性与真实请求。没有增加正则删除正文，也没有要求每次输出必须变化。

原文和轻整理的 system prompt 与基线快照逐字相同，已对 20 条文本的两个档位共 40 种组合检查。版本号变化记录的是整套构造器版本，不表示另外两档策略被改写。

## 复跑方式

离线检查不请求模型：

```sh
node --import tsx scripts/diagnostics/refinement/refinement-quality.ts
node --import tsx scripts/diagnostics/refinement/writing-controls.ts
```

真实调用必须显式提供 `--live`、已有 profile 目录和唯一的输出标签。每条样例每个所选档位会发一次请求，可能产生供应商费用。默认最多两个请求并发，不自动重试。`--prompt-file` 可选，用于加载原有 prompt 快照作对照；相对导入仍按生产模块目录解析。

```sh
electron scripts/diagnostics/refinement/refinement-live.cjs \
  --live --profile /absolute/path/to/existing-profile \
  --label unique-run --levels strong
```

报告包含合成输入、实际输出、最低约束、prompt 哈希与版本。执行耗时只用于排查，不作为加速基准。脚本不向用户配置写入任何字段；检测到配置在运行期间变化会报错。

## 上屏确认的实现与验证

过去 native 返回 0 只代表发出 Cmd+V，主进程却把它当成写入成功。新的主进程先取有界、安全的目标快照，发出一次粘贴后，在 400 ms 的轮询预算内比较同一目标的预期完整替换文本。AX 单次读取本身也有时间预算，因此 400 ms 不是绝对的端到端耗时上界。

- 只有同一目标读回精确匹配才标记 `verified`，等长错误也不能通过。
- 安全输入或 IME 组字会阻止自动写入。原生层在发事件前再检查一次。
- 目标变化、文本不匹配、AX 不可读或派发异常标记 `unknown`，打开带提醒的结果卡，不自动再次粘贴或覆盖剪贴板。
- 明确未派发时才允许手动剪贴板降级。原生 `-2` 仅表示权限/事件创建在派发前失败，不是任意错误的通用重试信号。
- 历史只保留方法、验证状态及错误分类，不保存为验证临时读取的整个输入框。
- 剪贴板恢复保留原有项目与各格式，且先检查 `changeCount`；有新复制内容时放弃旧恢复。

验证证据：

```sh
node scripts/diagnostics/audio/insertion-verification.cjs
node scripts/diagnostics/audio/clipboard-ownership.cjs
bash scripts/build-native.sh InputHelper
electron scripts/diagnostics/audio/insertion-native.cjs --native
```

最初 11 个隔离边界测试在旧实现失败 10 个；修改后通过，并补充原生错误码与异常分支，共 14 个通过。真实 Swift 代码在命名剪贴板上通过多项目/HTML 格式恢复和所有权检查，不操作用户的全局剪贴板。InputHelper 的 arm64/x86_64 构建通过；实际 Electron 测试窗口收到包含 emoji 的合成文字，并由 AX 确认，未在用户的真实输入框派发文字。

**剩余限制：** 验证窗口只覆盖一个 Electron textarea，不代表已验收所有聊天软件、终端、编辑器或富文本控件。AX 不可读、长字段超出快照上限，或编辑器规范化了换行/空格时，会保守地显示无法确认。一次快照确认也不能排除目标随后修改或回滚文字。跨应用验收仍需继续，不能放宽成“返回 0 就算成功”。

## 用户反馈后的括注修正

用户提供的结果包含“预订机场停车位（便宜的位置很快就没有了）”和“收拾登机箱（只住两晚，够用）”，并明确不接受这种自动括注。核对时设置为深整理、自然风格，无自定义提示词。

根因是 `.2` 的生产 prompt 明确要求把理由写为 parenthetical phrases，中英文示例和质量样例还鼓励优先使用括号。旧版真实返回值已含括号，写入环节只规范末尾空白，不是它加的括号。这是之前策略和验收标准的错误，不是未接入大语言模型。

`.3` 删除了这项引导，改为将有效理由融入普通句子。明确撤回的旧方案直接省略；用户明确口述或原样引用的括号仍然保留。不在后处理阶段机械删括号或删除其中的事实。原文和轻整理 prompt 对比旧快照，22 条样例的两个档位共 44 种组合逐字一致。

| 批次 | 请求数 | 请求错误 | 全部最低内容约束失败 |
| --- | --- | --- | --- |
| `parentheses-baseline-20261024` | 4 | 0 | 2：中英文待办仍添加括注 |
| `parentheses-fixed-20261024` | 22 | 0 | 4：中英文理由口语残留、标题口令、拼写解释残留 |
| `parentheses-final-20261024` | 22 | 0 | 4：中英文理由口语残留、话题未分段、重复强调丢失 |

本轮增加 48 次请求，未重试或切换模型。中间版与最终版的源文件快照分别保存在对应批次目录。最终样本中，中英文待办没有自动括注；改口案例没有旧计划旁注；明确要求的括号得到保留。**这只证明本轮括注检查通过，不代表 22 条质量验收全部通过。** 其余失败仍需处理，重复强调丢失尤其不能被“文字更简洁”掩盖。

最终中文待办的真实模型输出为：

```text
周五之前：
1. 先订机场停车位，因为便宜的位置很快会被订完。
2. 网上值机。
3. 收拾行李。只住两晚，带登机箱就够了。
```

这段已无括号，但第三项仍偏口语，因此最低书面化约束失败。不能用人工改写的理想答案替换它来展示成效。

同一段真实模型输出已送入生产 `insertText`，在专用测试窗口核对多行中文 DOM 值和 AX 读回，两者精确匹配并返回 `verified`；没有测试其他应用输入框，也未改写真实历史记录。

```sh
electron scripts/diagnostics/audio/insertion-native.cjs --native \
  --evaluation-report .build/refinement-evaluation/parentheses-final-20261024/results.json
```
